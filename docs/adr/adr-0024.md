# ADR-0024 — Structured logs by default: format lifting in `transform/logs`, Drain templating, message-as-body

- **Status**: Accepted
- **Date**: 2026-08-26
- **Deciders**: Tech Lead
- **Context**: Conduit's V0 logs pipeline parsed the syslog envelope (regex → `process` / `pid` / `message` attributes) and computed a `normalized_message` grouping column with four hand-rolled masking regexes. Field use on real hosts exposed four weaknesses at once:

  1. **The macOS parser silently missed most lines.** macOS senders routinely contain spaces (`Jamf App Installers[8033]:`), which the `\S+`-style process token could never match — those lines shipped raw, with no `process`/`pid` attributes at all. Real install.log captures showed the majority of records unparsed.
  2. **`normalized_message` is a weak template.** Fixed regexes (mask UUIDs, IPs, `key=value` values, 4+-digit numbers) can't learn that `MSU_UPDATE_25G83_patch_26.6.2_major` or `1Password 8 8.12.34` are the variable parts of a line family. It also duplicated ~every message's bytes onto every record.
  3. **Only JSON bodies were structured.** logfmt (logrus text), klog/glog headers, and plain `ERROR: ...` prefixes — three of the most common formats the agent actually tails — got no severity, no message lift, no trace correlation.
  4. **Two latent correctness bugs.** The JSON trace/span-id lift was dead code (an unset pdata id reads back through OTTL's `.string` accessor as the zero-hex string, never `""`, so the `== ""` guards never fired), and journald severity was never mapped (the receiver leaves severity unset; everything defaulted to INFO — including kernel errors). `transform/logs` also ran with the upstream default `error_mode: propagate`, so one malformed record could fail its whole batch.

  Meanwhile upstream contrib (at our pinned v0.152.0) ships `drainprocessor` — the Drain log-clustering algorithm as an annotate-only processor: it learns templates across records and stamps each with `log.record.template`. That is precisely the job `normalized_message` was approximating.

- **Decision**: Restructure the default logs pipeline on **every distribution/profile** around three moves:

  **1. The record body is the log *message*; the envelope is metadata.** The linux/darwin filelog operators parse the syslog envelope and then `move` the message into `body` (unparseable lines keep their raw body via `on_error: send`). The journald fragment does the equivalent: severity from `PRIORITY` (0-2→FATAL, 3→ERROR, 4→WARN, 5-6→INFO, 7→DEBUG), `process` ← `SYSLOG_IDENTIFIER`, `pid` ← `_PID`, `systemd.unit` ← `_SYSTEMD_UNIT`, then `body` ← `MESSAGE` (dropping the ~35 journal bookkeeping keys). This revises PROFILE_SPEC's "body preserved verbatim" rule: the envelope's timestamp/hostname/process[pid] duplicate fields the record already carries authoritatively (observed time, `host.name`, attributes), and keeping them in body both clutters every Honeycomb row and poisons Drain templates with the current date as a literal token (a new cluster per day). The darwin regex is rewritten to handle multi-word senders and the launchd `(job-label)` form (new optional `sender` attribute); empty optional captures are removed instead of shipped as `""`.

  **2. `transform/logs` becomes the format-structuring stage** (`error_mode: ignore`), with seven ordered blocks: (1) credential redaction (unchanged, still first so nothing downstream can copy a secret); (2) JSON lift — now including ECS `log.level` and with the trace/span guards fixed to compare against the zero-hex ids; (3) logfmt lift via `ParseKeyValue`, gated on the body starting with a `key=value` pair and containing a level/message key; (4) klog/glog `[IWEF]mmdd` header → severity; (5) leading level token (`ERROR: ...`, `[warn] ...`, `WARNING:root:...`) → severity, anchored at start-of-body; (6) one shared severity_text→number mapping that also canonicalizes the text (`warn`/`Warning`/`notice` → `WARN`/`WARN`/`INFO`) so Honeycomb sees a single severity vocabulary; (7) default INFO.

  **3. `drainprocessor` replaces `normalized_message`** as the always-on grouping column, appended to the logs pipeline after `transform/logs` (so it learns from redacted, restructured bodies) on all profiles. Config: `max_clusters: 1024` (LRU-evicted memory bound), `extra_delimiters: ["="]` (keeps key names literal in templates), and `body_field: message` on windows only (windowseventlog emits map bodies; linux journald is already reshaped at the receiver). Output lands in `log.record.template`; dashboards' Top Log Templates panels group by it. The `normalized_message` block is deleted — Conduit is pre-1.0 and the column's only consumers were our own dashboards, updated in the same change.

  A new `internal/collector` DryRun test loads every profile's rendered YAML through the real factory map (which builds pipelines — OTTL statements and stanza operator chains included), per-GOOS, so "expander tests pass but the binary won't boot" configs fail in CI rather than on a host.

- **Consequences**:
  - Every mac line family from the motivating capture now parses (`process`, `pid`, and `sender` where present), and JSON/logfmt/klog/level-prefixed app logs get severity, message, and trace correlation on every platform.
  - Honeycomb grouping moves from a per-record rewrite to a learned, adaptive template. Trade-offs accepted: `drainprocessor` is **alpha** upstream (knobs may shift across our pinned minors; acceptable pre-1.0 with the pin from ADR-0014); templates are learned in-memory per process, so early records after a restart may carry over-specific templates until clusters converge (`seed_templates` via `overrides:` is the stabilizer for known-noisy fleets; since the collector pin moved to v0.158.0 the tree is also snapshotted through `file_storage` whenever `output.persistent_queue` is enabled, so restarts resume the learned state); and two agents can converge on cosmetically different templates for rare lines.
  - Records are leaner: no duplicated message bytes (`normalized_message` gone, journald bookkeeping dropped, envelope no longer in body). Operators who need the raw journal record or raw syslog line re-enable them via `overrides:` (ADR-0012).
  - `severity_text` is now a closed vocabulary (TRACE/DEBUG/INFO/WARN/ERROR/FATAL) for agent-derived severities; OTLP-supplied values pass through untouched.
  - Record timestamps still come from filelog's observed time, not the parsed envelope timestamp (dropped as before). Fine while `start_at: end` tailing is the only mode; a backfill feature would need `time_parser` routing (BSD-format lines lack a year), noted as future work.
